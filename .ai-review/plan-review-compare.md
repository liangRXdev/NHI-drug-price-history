## 2. 架構風險

| 嚴重度 | 問題 | 為什麼現在不修之後會更貴 | 建議修法 |
|---|---|---|---|
| **High** | **§10 第一步把「共用語意」誤等同於「單品項必須改成 N 序列介面」。** 既有 `summaryAt`、`selectMeta`、狀態標籤與 `chartModel` 已分開；摘要重用不以改造圖表入口為前提。 | 先強制遷移單品項，會擴大回歸範圍，也把尚未定案的 band／基準規則固化。 | 把驗收要求改成「單品項與比較頁共用每代號判定規則，結果符合相同契約」。允許保留單品項契約，由比較功能組合各代號結果；不以必須接受 N 組 records 作為通過條件。 |
| **High** | **現有圖表模型不能被視為完整的比較模型。** 它已有各自 X/Y 範圍、開放右界、`unpriced_zero`、`unknown` 與獨立 gaps；比較規格另需共同座標、priced band、任意日期查詢及區間基準。 | 如果先宣布「重用即完成」，後面才補跨序列語意，會反覆改動共同模型。 | 第一步前先定義共用日期範圍、每代號狀態及輸出歸屬的不變條件。特別驗證：另一代號有較晚預告時，本代號開放區間仍覆蓋共同右界；移除其他代號不改本代號历史事實。 |
| **High** | **效能目標可能暗含未宣告的啟動架構變更。** 既有啟動等待 index 與 meta 才進入 ready；冷開比較 deep link 若沿用此流程，仍負擔已實測數秒的 index。§8 的 `<600 ms` 未說是否包含它。 | 若到最後才按冷啟動驗收，可能被迫改啟動依賴或資料模型。 | 分別定義冷開 deep link、搜尋後進比較、已快取重繪的量測起訖。若本期不改啟動依賴，就不得承諾冷開 600 ms；這不構成重新要求修復已接受的 E7。 |
| **Medium** | **「首屏增加 0 bytes」字面不可驗收。** 搜尋卡入口與比較籃本身就有新增成本；共用 engine 若加內容仍在首屏載入。SW 預取外殼也會影響總傳輸量。 | 後期可能為滿足字面數字而做不必要拆分，仍無法證明零增量。 | 改為「未進入比較前不載入比較專用視圖資源」，並量測入口／共用層實際增量；定義是否含 SW 預取。原生 module 可相容於無 build step，無須引入打包器或框架。 |
| **High** | **快取契約只有『已載入 Map』，不足以保證併發去重與混批防護。** 同片首次並行請求、重試、meta 換版後的已快取片，尚未定義一致行為。 | 若快取鍵及驗證生命週期定錯，會同時影響單品項與比較页。 | 規定同一版本、同片的進行中載入亦須共享；失敗可重試；快取命中仍須符合本次 meta 的預期版本。不得混用不同 meta 批次；維持 `data/` 不經 SW。 |

**獨立判斷：§10 說對了「不可產生第二套判定規則」，但錯把特定重構方式當成必要條件。** 真正最難回頭的是每代號的日期／未知狀態契約，以及選取集合與版本的一致性；不是函式參數從一組變 N 組。

## 4. 更簡單的替代方案

| 嚴重度 | 問題 | 為什麼現在不修之後會更貴 | 建議修法 |
|---|---|---|---|
| **High** | N 序列共用核心被預設為唯一方案，超過「並列且語意一致」所需。 | 額外牽動已完成的單品項流程與測試。 | **保留每代號獨立推導，比較層只負責共同範圍、排列與呈現。** 是否需要調整共用契約，由已定案的不變條件決定；不要求一次全面遷移。此方案維持原有目標及所有平台限制。 |
| **High** | **相對變化模式本期成本偏高、增益有限。** 它新增基準、裁切、預告、未知值與圖例一致性問題；目標 4 已可由各碼「總變化」並排回答。 | 寫完再撤掉，會留下模式狀態與測試負擔。 | **建議本期延後指數圖，但保留各碼歷史首筆至 T 的總變化。** 這是對 §4.1 已承諾功能的範圍縮減選項，須由使用者決定；不是把它當成非必要後自行省略。 |
| **Medium** | 即使保留指數圖，基準跟著 preset 移動也使相同日期的值改變，增加誤讀與驗證成本。 | 所有區間切換皆成為計算狀態切換。 | 可改採**固定歷史首筆有價基準**，preset 只裁切畫面；圖例固定列出各自基準。這更貼近目標 4，但屬替換既定模式語意，需明確修訂規格。 |
| **Medium** | CSV 同時承諾完整與目前篩選兩種輸出，卻未定義失敗及篩選邊界。 | 每一種視圖狀態都增加匯出分支。 | 若同意縮減本期範圍，先只提供完整事件 CSV，且所有選定碼成功後才可匯出；保留日期、rawPrice、來源與參考日。 |

**建議動工前優先定案：完整狀態表、相對模式基準、URL 合併順序、部分失敗輸出矩陣，以及取消「必須先改成 N 組 records」的架構門檻。**
