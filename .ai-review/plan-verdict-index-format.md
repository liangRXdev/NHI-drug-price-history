## 判定表

| # | 項目 | 覆審嚴重度 | 判定 | 理由 |
|---|---|---|---|---|
| 1.1 | 舊格式基準產物未定義 | Blocker | **接受** | 屬實。F1／F2／F4 若由待測轉換器反解出「舊格式」再自我比較，就是「斷言的期望值由受測程式產生」。修法：legacy oracle 取自本次改版前的 commit，以 SHA-256、筆數、dataVersion 三者鎖定 |
| 1.2 | missing→null 與「內容不變」矛盾 | High | **接受** | 屬實。**已實測驗證**覆審的查證：45,179 筆 × 14 欄、45,258 列 × 13 欄**全部存在**，無缺 key、無額外欄位；僅 `lastPriceChangeDate` 有 4,749 筆是顯式 `null`。故採方案一：所有規定 key 必須存在，缺 key＝轉換失敗不得發布 |
| 1.3 | window 索引公式有歧義 | High | **接受** | 屬實，是本方筆誤。`rows[i][N][k]` 取到的是第 k 個 window **列**而非第 k 個**欄**。正是「兩個獨立實作者會做出不同東西」的實例 |
| 1.4 | 必要欄位集合不完整 | High | **接受** | 屬實。已實測確認 UI（`app.js:240`／`412`）確實讀 `strength`／`strengthUnit`／`dosageForm`／`manufacturer`／`atcCode`。本方自查的 S2 只列了 `searchCard` 函式讀的欄位，範圍比覆審小——**覆審這項比自查完整** |
| 1.5 | 值域與型別契約不足 | High | **接受** | 屬實。「型別與舊格式相同」不可執行。附逐欄型別表，沿用 `spec.md` 既有語意，不新增臨床規則 |
| 1.6 | rows 空／代號重複／排序未封閉 | Medium | **接受** | 屬實。`[新增需求]` 的 `rows.length > 0` 部分**不判範圍蔓延**：空 index 會讓站台進 `ready` 並顯示「查無結果」，正是本專案威脅模型最怕的「靜默錯誤」形態，屬既有 invariant 的形式化 |
| 1.7 | 一次性轉換失敗路徑未定義 | Medium | **接受** | 屬實。沿用既有 builder 的 fail-closed／全有全無契約 |
| 1.8 | 前次 index 消費契約未涵蓋 | Medium | **部分接受——嚴重度低估，升為 Blocker** | 問題屬實但**評級錯誤**。實查 `build_price_history.py:327-328`：`prev_codes = {d["code"] for d in prev_index["drugs"]}`。改 columnar 後 `prev_index["drugs"]` 不存在 → `prev_codes` 成空集合 → **消失代號 guard（`max_disappeared_pct=1`）靜默失效**，資料災難性縮水可直接發布，且要到下週日排程才顯形。這不是「下一次排程才失敗」，是「下一次排程**不會失敗**但防線已經不在」 |
| 1.9 | HTTP／逾時／重入契約 | Low | **接受** | 屬實。明寫只有成功解析後的 format／dataVersion 不符才是 mismatch |
| 2.1 | 「同一 commit 無順序風險」不成立 | High | **接受** | 屬實，**本方 v0.1 的判斷錯誤**。`spec.md` §7 自己就寫「CDN 快取約 10 分鐘，已開啟的頁面或全新載入都可能取得不同批次的檔案」——本方寫 §8 時沒把這條套用到自己身上 |
| 2.2 | 抽驗位置式資料與臨床風險不相稱 | High | **接受** | 屬實，且是 v0.1 最危險的一條。位置式格式的核心風險就是單列錯位仍為合法 JSON → 靜默顯示另一欄的價格。修法（與 prepare 必經 traversal 合併）不增加第二次掃描，本方原本擔心的效能理由不成立 |
| 2.3 | JS／Python 等價與全量驗證衝突 | High | **接受** | 屬實，v0.1 §4.1 與 §5.4 確實互相矛盾。分兩層契約：共通 schema／reason 規則必須等價；覆蓋範圍分 profile |
| 2.4 | 最難回頭的是 schema 不是 (a)/(b) | High | **接受** | 屬實。原型前先凍結 schema、型別表、null 規則、索引公式；(a)/(b) 續留待量測 |
| 2.5 | direct rows 外洩成第二套資料模型 | Medium | **接受** | 屬實。列為架構 invariant |
| 2.6 | dataVersion 保持不變是正確決策 | 無缺口 | **確認** | 無需動作 |
| F1 | 等價比對可循環 | High | **接受** | 屬實，與 1.1 同源 |
| F2 | mask 全 false 仍相等 | High | **接受** | 屬實。這是恆真斷言的變形——fixture 必須同時含 true 與 false |
| F3 | 「多個 T」未指名反例類別 | High | **接受** | 屬實。T 的產生規則要明寫，報告要輸出實際唯一 T 數與各類別命中數 |
| F4 | round-trip 可循環 | Blocker | **接受** | 屬實。F4 是唯一宣稱能證明「所有欄位沒變」的條件，循環了其他驗收就只看部分行為 |

| F6 | 必要欄位清單自身可能漏 | High | **接受** | 屬實。14+13 欄逐一刪除測試 |
| F7 | 兩端互比而無獨立 expected | High | **接受** | 屬實。**與既有日期 validator 的教訓同形**（JS 收 `2027-02-30`、Python 收 `20260911`）。每案必須帶獨立 expected |
| F8 | 測試數量只能證明數量 | Medium | **接受** | 屬實。改列必跑 suite 與 mandatory test ID，數量只作資訊 |
| F9 | guard 未接入發布路徑 | Medium | **接受** | 屬實。要經完整 build/publish 路徑測，且 fail 時 data/status 均不得變動 |

**需重審**。
