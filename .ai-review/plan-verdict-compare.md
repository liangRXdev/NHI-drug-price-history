## High

| # | 項目 | 判定 | 理由 |
|---|---|---|---|
| H1 | §4.3 的四態 band 不是完整狀態模型（缺 `missing`、`malformed`、衝突、首筆前、末筆後） | **接受** | 屬實。`spec.md` §5.3 有五種 priceState，§4.5 的 tooltip 表自己也列了「來源衝突」，但 §4.3 的 band 只有四態。「有紀錄但價格未知」與「無紀錄」合併是實質誤導。可共用異常視覺樣式，但語意不得合併；衝突列不得被選為確定價格或指數基準。 |
| H2 | §4.1「顯示區間內自己第一筆 `priced`」有兩種不同答案 | **接受** | 屬實且有實證。`A020296321` 最後一筆為 2014-07-01 起、`to: null`、20.50 元，持續有價至今；但「近 3 年」preset 區間內**沒有任何 `from` 落在其中**。照字面實作會判「此區間無有價紀錄」而不畫線——該藥明明近三年一直有給付價。<br>**修法**：定義為「顯示區間內最早**有效**的可唯一判定有價日期」，允許起日在左界之前但仍有效的 record；圖例分列基準觀測日與原紀錄起日。 |
| H3 | §1 目標 4 與 §4.1 相對模式不一致 | **接受** | 屬實。目標 4 問「從各自最早有價紀錄到現在」，§4.1 的基準卻隨 preset 移動，§4.4 又讓預告進入畫面。兩者是不同問題，不可混稱。 |
| H4 | §6 部分失敗只定義橫幅，未定義整份比較結果的完整性 | **接受** | 屬實，且與 CSV 的「完整列」定義直接衝突：4 碼中 1 碼失敗時，「完整事件 CSV」到底含幾碼未定義。失敗不得偽裝成空窗。須補「同一選取集合 × 載入中／完整成功／部分失敗／全部失敗／混批」的輸出矩陣。 |
| H5 | §10 第 1 步把「共用語意」誤等同「單品項必須改成 N 序列介面」 | **接受** | 屬實且有程式碼證據，**推翻本覆核者先前把 §10 第 1 步評為「整份規格最好的一段」的評價**。`engine.js` 已把 `summaryAt`、`selectMeta`、`stateLabel`、`chartModel` 分為獨立純函式；摘要重用不以改造圖表入口為前提。強制先遷移單品項會擴大回歸範圍，並把尚未定案的 band／基準規則提前固化。<br>§10 的**判斷方向對**（不可產生第二套判定規則），但**手段被過度指定**。改為驗收「單品項與比較頁共用每代號判定規則、結果符合相同契約」，不以函式簽章從 1 組變 N 組為通過條件。 |
| H6 | §8 效能目標暗含未宣告的啟動架構變更 | **接受** | 屬實。`app.js:75-95` 啟動時等 `status.json` ＋ `drug_index.json` ＋ `meta.json` 才 ready；冷開 `?codes=` deep link 若沿用此流程，仍要背 index 的 2.99 MB gzip／中位 4,634 ms。§8 的「< 600 ms」不可能含它。<br>**修法**：分別定義冷開 deep link／搜尋後進比較／已快取重繪三種量測起訖。本期若不改啟動依賴，就不得承諾冷開 600 ms。這不等於重開已接受的 E7。 |
| H7 | 快取契約只有「已載入 Map」，不足以保證併發去重與混批防護 | **接受** | 屬實。同片首次並行請求、重試、meta 換版後的已快取片都未定義。須規定：同版本同片的進行中載入亦須共享；快取命中仍須符合本次 meta 的預期版本；維持 `data/` 不經 SW。 |

## Medium

| # | 項目 | 判定 | 理由 |
|---|---|---|---|
| M1 | §4.4 X 軸與日期生命週期不足 | **接受** | 屬實，且 §4.4 內部就矛盾：文字寫「已生效紀錄的聯集」，公式卻含 `max(今日, 最後一筆預告起日)`。另需明定一次比較共用同一個 T，時間篩選不改摘要 T 或描述欄位選列日期。 |
| M2 | §3.3 與 M5 的 `?code=` 合併規則自相矛盾 | **接受** | 屬實。§3.3 限「未重複、未超過 4 個」才放首位，M5 卻無條件要求首位。須明定處理順序：讀取 → 清洗 → 去重 → `code` 合併 → 截斷 → 計算略過數。 |
| M3 | §3.3 URL 異常與 sessionStorage 優先序未封閉 | **接受** | 屬實。含本覆核者先前指出的「清洗後只剩 1 碼」，另有連續逗號、重複參數鍵、編碼異常、URL 與 session 不同、返回後重新整理。須明定 URL 優先於 session，並區分「格式不合法／確認不存在／載入失敗」三者。 |
| M4 | §4.2／§5.2 把「選定」「可見」「表格篩選」混為一談 | **接受** | 屬實。圖例 toggle 說隱藏序列，§5.2 說等同表格篩選，§4.5 又要求 crosshair 列出**所有**選定代號。建議隱藏不改選取集合、不改序位、不改摘要與基準；crosshair 保留該列並標示已隱藏。 |
| M5 | §6 失敗／競態終態不足 | **接受** | 屬實。須補有限逾時；只有確認不存在才顯示「查無」。 |
| M6 | §5.2 合併表缺迄日與 `invalidRecords` | **接受** | 屬實，與 §2「異常列僅計數並連回詳細頁」及「完全沿用 §8.3 標註」互相矛盾。異常日期不得硬排成有效日期。 |
| M7 | §8「首屏增加 0 bytes」字面不可驗收 | **接受** | 同 spec-upcoming M8，一併處置：改為「未進入比較前不載入比較專用視圖資源」，入口與共用層增量另行量測。 |
| M8 | §9 golden 組合「一次覆蓋四種 band 型態與 M9、M12」不成立 | **接受** | 屬實，實測確認：`AC48092100` 只有 priced；`AC48867100` priced／terminated／relisted；`B009254100` priced／suspended／terminated；`A020296321` 首列 0 元＋後續 priced。**四者 flags 全為空，無一帶 `gap`**，第四種 band（空窗）未覆蓋。宣稱須改寫。 |
| M9 | M9 只能條件式覆蓋；`A020296321` 首段事件是 `initial` 不是 `terminated` | **接受** | 屬實，實測確認：該代號首段 1995-03-01～1998-02-28 為 `priceState: terminated` ＋ `eventType: initial`，其後有 5 筆 priced。若實作把 `everPriced` 當**整個代號**的布林值，該測試會直接跳過或反向。須把 `everPriced = false` 明定為「**該列之前**從未有價」，並直接指定首段日期與預期文案。與 spec-upcoming H1 同一根因。 |
| M10 | 真實的兩個 gap 代號殺不掉「不處理 gap」的弱化實作 | **接受** | 屬實，實測確認：`BC23981100` 空窗 2019-12-01～2020-11-30，**兩側皆 suspended**；`A035680329` 空窗 2010-09-01～09-30，**右側 terminated**。兩者都沒有 `priced → gap → priced`，所以「只因終止／暫停就斷線、完全不處理空窗」的實作在兩個真實代號上都會綠。<br>**這比本覆核者先前的發現更深**：先前只指出建議組合裡沒有 gap 代號；即使換成 gap 代號仍殺不掉該變異。必須另加 `priced → gap → priced` 合成反例（含兩側同價與異價）。 |
| M11 | 合併表／CSV／marker 沒有守恆驗收 | **接受** | 屬實。重複一列、漏一列，列數檢查都抓不到。須按代號與原紀錄逐筆比對內容與出現次數。 |
| M12 | 四碼靜態截圖驗不到固定序位、預告線型與完全重合序列 | **接受** | 屬實。人工驗收須加入移除／重加、預告、四線重合、手機觸控情境。 |
| M13 | §8 無效能驗收程序 | **接受** | 屬實。最大片 0.123 MB gzip 不能直接證明四片 600 ms 可達。須指定具名 shard、冷暖快取、字型／SW 條件與重複次數。 |
| M14 | §5.3 CSV 同時承諾「完整」與「目前篩選」兩種輸出 | **部分接受** | 問題屬實且本覆核者獨立發現（括號那句「不受畫面篩選影響時另備一個『匯出目前篩選』選項」語意破碎，且與 `spec-upcoming` §5.4 的匯出慣例相反）。但 Codex 的修法「本期只提供完整事件 CSV」是範圍縮減。<br>**採較小修法**：統一為「匯出目前篩選結果，檔頭註明篩選條件與來源」，並依 H4 規定未完整成功時停用匯出。兩份規格的 CSV 慣例一併對齊。 |

## 修訂指示（Step 5）

不依賴 S1／S2 的部分可立即修訂：

1. §4.3：改為完整狀態判定表，補 `missing`／`malformed`／衝突／首筆前／末筆後（H1）
2. §6 ＋ §5.3：補部分失敗的輸出完整性矩陣，失敗不得偽裝成空窗（H4）
3. §10 第 1 步：改為「共用每代號判定規則、符合相同契約」，移除「必須改成 N 組 records」的門檻（H5）
4. §8：分三種量測起訖；不承諾冷開 600 ms；0 bytes 重新定義（H6、M7）
5. §2：補併發去重與快取版本一致性（H7）
6. §4.4：修正「聯集」與公式的矛盾，明定共用 T（M1）
7. §3.3 ＋ M5：明定 URL 處理順序（M2、M3）
8. §4.2／§4.5／§5.2：明定選定／可見／篩選三者的影響範圍（M4）
9. §6：補有限逾時與各終態（M5）
10. §5.2：納入迄日與 `invalidRecords`（M6）
11. §9：golden 組合宣稱改寫；`everPriced` 定義釘死為「該列之前」；加 `priced → gap → priced` 合成反例；M1–M14 全面改寫為堵死弱化版本的斷言；補守恆驗收、人工驗收情境與效能驗收程序（M8–M13）
12. §5.3：CSV 統一為「匯出目前篩選結果」（M14）

S1／S2 定案後再修 §4.1、§4.2、M10、M11、§10 第 5 步、§11.2。

**修訂後須重跑 `/codex-checkplan`**：H1、H4、H5 更動了狀態模型、輸出契約與重構門檻，屬架構層變更。
